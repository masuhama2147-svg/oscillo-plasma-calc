## 1. 初心者向け—このソフトは何ができるか

### 1.1 一行で言うと

「**オシロスコープと分光器で取った数字を入れたら、研究者が次に何を判断すべきかが画面に出る**」ためのソフト。

### 1.2 たとえ話

野村研究室の研究は、料理に置き換えるとこんな感じ:

| 料理工程 | プラズマ研究での対応 |
|---|---|
| ガスコンロの火加減 | プラズマに入れる電圧と電流（オシロで測る） |
| 鍋のなかの温度 | プラズマ内の電子温度・密度（分光器で測る） |
| できあがった料理の味 | できた油・メタノールの量（GC で測る） |

これまでは 3 つの計測機の数字を **エクセルで手計算** で結びつけていたため、数時間かかった上に計算ミスも起きていた。本ソフトは

1. 火加減の数字（オシロ CSV）を入れると **電力・エネルギー** が出る
2. 鍋の温度の数字（分光強度）を入れると **電子温度・密度** が出る
3. 料理の量（GC モル数）を入れると **CO₂ 変換率・油合成効率** が出る
4. それぞれ **「典型値からズレてないか」** を自動チェックして、ズレてたら原因候補と参考論文まで出す

これを **ブラウザの画面** で全部できるようにしたものが本ソフト。

### 1.3 なぜそれが大事か

油合成研究は、3 つの数字（電力・プラズマ温度・生成量）を **同時に** 追わないと「なぜうまくいったか／いかなかったか」が説明できない。本ソフトは全部 **同じ画面で見られる** ので、研究室メンバー全員が同じ言葉で議論できるようになる。

### 1.4 起動するには

```bash
cd ~/Downloads/野村研究室計算ソフト開発
.venv/bin/shiny run --port 8000 src/oscillo_plasma_calc/ui/app.py
# ブラウザで http://127.0.0.1:8000 を開く
```

Windows の人は `launch_ui.bat` をダブルクリックでも OK。

## 2. フロントエンド実装の詳細レポート

Shiny for Python（v1.6+）で実装。**9 タブ構成**、画面上部に並ぶナビゲーションバーから切り替える。

### 2.1 共通要素（全タブに常駐）

#### ヘッダ
- アプリ名「液中プラズマ オシロスコープ解析」
- 9 タブナビゲーション
- KaTeX（数式描画）の CSS/JS と MutationObserver を head 部にロード — Shiny の動的 DOM 更新でも数式が即時描画される設計

#### サイドバー（Upload タブのみ）
- 入力タイプ選択（既存 xlsx / 別 xlsx パス / CSV アップロード）
- **図表モード切替**（`Screen（解析用）` / `Paper（論文補助図）`）
- パルス繰返し周波数 PRF
- DC オフセット補正 ON/OFF
- 立ち上がりエッジ同期 ON/OFF
- コンセント側総消費電力（任意、装置効率比較用）

### 2.2 各タブの実装内容

#### ① Upload タブ（最初に開く画面）

3 ステップ構造で、CSV / xlsx を読み込んでから次のタブへ送る。

**STEP 1 — CSV の形式仕様**
- 受け付ける CSV の形式を **画面に常時表示**（time_s, voltage_V, current_A の 3 列必須）
- ▼「詳しい仕様と注意点」を展開すると、メタデータ行・単位・行数上限・NG 例まで列挙
- これで「形式違反 → 計算失敗 → 何が悪いか分からない」という典型的なつまずきを根本から防ぐ

**STEP 2 — 読み込み結果とバリデーション**
- 読み込み成功時の **8 枚カード**（grid 表示）:
  - サンプル数 N
  - Δt / fs（時間分解能・サンプリング周波数）
  - 観測窓 T
  - Vpp（kV）
  - Ipp（A）
  - PRF（Hz）
  - DC オフセット（V/I 別表示）
  - 装置予算余裕度（1 kW ルール）
- 4 段階バリデーションバナー（赤 error / 黄 warning / 青 notice / 緑 ok）
  - 列名違反 → 赤バナー + 修正案
  - Δt のばらつき > 5 % → 黄バナー
  - DC オフセット過大 → 青バナー + 推奨処理
  - 各種 OK → 緑チェック

**STEP 3 — 次にすること**
- 警告内容に応じて **動的に推奨タブ** をリストアップ
  - 立ち上がり時間が異常 → Waveform タブで拡大確認 を最優先
  - 装置予算超過 → Electrical タブで P_eff を見直し
  - 警告なし → 通常順序（Electrical → FFT → Chemistry → Export）

**コンセント比較ブロック**（W_socket 入力時のみ表示）
- W_socket、観測窓平均 P̄、プラズマ投入割合 P̄ / W_socket %
- 70 〜 95 % で妥当判定

#### ② Waveform タブ

- 上部に「▼ このタブの読み方」ガイドパネル（双極性・誘導性／容量性の判別基準を解説）
- plotly 双軸グラフ:
  - **青線 V(t) [V]**, **赤線 I(t) [A]**, 横軸 [μs]
  - **マーカー注釈**: Vmax, Vmin（青三角）, |I|max（赤ダイヤ）
  - **vline 注釈**: 10% rise / 90% rise / zero-cross
- 図表モード `Paper` 選択時は白背景・整った凡例・線幅統一に切替

#### ③ Electrical タブ

- 読み方ガイドパネル
- **左ペイン**: P(t) [W] と **累積エネルギー E(t) [J]** を双軸でオーバーレイ
  - |P|max を黄色 hline で注釈
- **右ペイン**: Lissajous 図（V vs q）
  - 左上に **loop area（J/cycle）と f（Hz）** のテキストボックス注釈
- **下部**: 電力・エネルギー KPI 表（量 / 値 / 単位 / 判定 / 根拠）
  - Ppeak, E, P̄, Lissajous P̄, E_pulse, Duty, P_eff, ⟨|P|⟩, Budget margin
- **会議要件のコンセント比較**ブロックも下部に表示

#### ④ FFT タブ

- 読み方ガイドパネル（駆動源と高調波・Nyquist の解釈）
- 両対数軸で V/I パワースペクトルを並列表示
- **vline 注釈 5 本**:
  - 1f（支配周波数、実線・濃色）
  - 2f, 3f（高調波、点線）
  - Nyquist（赤実線）
- Nyquist より上の領域に **薄赤色の信頼外帯**を描画

#### ⑤ Plasma タブ

- 読み方ガイドパネル（典型値・気相 Paschen 限界の注意）
- サイドバー入力（13 ウィジェット）:
  - Boltzmann 2 本線法: I_ij, I_kl, g_i, g_k, A_ij, A_kl, ν_ij, ν_kl, E_i, E_k
  - Stark: Δλ_{1/2}, α
  - Ohmic: σ, E
  - 非平衡診断: T_gas
  - Paschen: p, d
- 計算ボタン → 右ペインに以下を出力:
  - **反応場診断 KPI 表**（Te, ne, Debye, f_p, E/N, ⟨ε⟩, T_e/T_gas）
  - 各物理量カード（compact=False、3 レベル解説 開展示）

#### ⑥ Chemistry タブ

- 読み方ガイドパネル
- サイドバー入力:
  - n_prod_mol, ΔH（kJ/mol）
  - **n_co2_in_mol, n_co2_out_mol**（変換率計算）
  - **C1 / C2 / C3 / C4+ weight fraction**（ASF α 推定）
- 計算ボタン → 右ペインに **油化判断 KPI 表**:
  - G値 / 化学効率η / SEI / EC / χ_CO2 / η_SE / ASF α
- 各物理量カード（compact=False）

#### ⑦ 励起温度 Te タブ

- 読み方ガイドパネル（タングステン推奨・R² 判定基準）
- サイドバー:
  - 元素選択（H/O/W/Al/Cu）
  - 強度 CSV ドラッグ&ドロップアップロード
  - 動的に元素別の発光線入力欄が生成される（H なら 3 本、O なら 6 本…）
- 計算ボタン → 右ペインに以下:
  - **Boltzmann plot プロット**:
    - 観測点（マーカー + 線ラベル）
    - LSM 直線フィット（赤破線）
    - 右上の注釈ボックスに **R²、採用線数 n、LTE 判定** を色分け表示（緑 ≥0.95、黄 ≥0.85、赤 <0.85）
  - **Te が nan/inf の場合**:
    - 赤いエラーパネルが上に出て、原因候補（採用線不足、E_u 差小、強度 0、自己吸収、感度補正、ラベル違い）をリスト化
  - 採用線・除外線一覧（折りたたみ）

#### ⑧ Trace タブ

このタブが「研究ノート・査読対応」の中核。

**最上部—解析サマリヘッダ**（sticky position）
- 計算済み総数 + ✓正常 / ℹ注意 / ⚠警告 / ✗異常 のカウントチップ
- 装置予算 1 kW チェックの結果を独立バナーとして常時表示

**研究者向けサマリ**（3 列 grid）
- **左**: 重要警告・注意 KPI 表
- **中**: 油合成・装置判断 KPI 表（重要 KPI を深刻度順）
- **右**: 論文・研究ノートに載せる候補値（Vpp, Ipp, E, P̄, Lissajous, P_eff, G, η, SEI, Te 等）

**主要 KPI の式ショートカット**
- 上位 6 KPI の `name: value` ヘッダ → クリックで KaTeX 数式 + 数値代入が即展開
- カード本体を開かずに「式と数値」だけ確認できる

**フィルタ + 展開コントロール**
- 全部 / ⚠警告・異常のみ / ✗異常のみ
- 全部開く / 全部閉じる
- すべてクライアントサイド JS（高速）

**カテゴリ別カード**
- ⚡ 電気系 / 🌡️ プラズマ診断 / 🧪 油合成 KPI / 🔌 装置運用
- 各カテゴリは深刻度順ソート、デフォルト閉
- カードをクリック → 🔰 初学者解説 → 🔬 研究者解説 → 🎓 博士解説 → 📐 理論式・数値代入 → ⚠ エラーライン詳細 の 5 段階展開

#### ⑨ Export タブ

- **Markdown レポートダウンロード**:
  - 先頭に「実験条件レビュー」（N, Δt, fs, T, PRF）
  - 「主要 KPI 表」（Markdown 表で paper-candidate を列挙）
  - 「異常値・注意値」リスト（anomaly_markdown）
  - 「図表の読み方」ガイド
  - 既存の物理量別 Markdown レポート
- **解析済み量 CSV ダウンロード**:
  - 列: `quantity, value, unit, status, source, equation_key`
  - 元波形ではなく **計算結果テーブル**（論文補助表に直接使える）

### 2.3 共通の UI 設計ルール（全タブで遵守）

- **色は意味で使う** — 緑=正常、青=注意、黄=警告、赤=異常（カラーブラインドにアイコン併記）
- **軸には必ず単位** — 全プロットで V, A, μs, MHz, eV 等を明示

## 3. 計算シミュレーション工学 専門家レビュー

> *仮想インタビュー: 数値計算・スペクトル解析・信号処理を専門とする工学博士の視点*

### 3.1 評価できる点

#### ✅ 数値計算ライブラリ選択が適切
- 積分は **`scipy.integrate.trapezoid` / `cumulative_trapezoid`**（合成台形則 O(Δt²)）。10,000 サンプル波形では誤差 < 0.1 % で、研究用途には十分。
- FFT は **`scipy.fft.rfft` + Hanning 窓**。サイドローブ抑制と計算速度のバランスが良い。
- ピーク検出に **`scipy.signal.find_peaks`** を prominence + distance で調整、ns-pulse 環境向けに `prominence=0.5·Vpp`, `distance=100ns` に固定。リンギングを 1 パルスに丸める設計が物理的に正しい。
- 微分は **中央差分（`np.gradient`）** O(Δt²)、片側差分の境界処理込み。**自前実装を最小化** している点が保守性の観点で優れている。

#### ✅ 単位系統の徹底
- すべて SI 統一。Te だけは入力 eV、内部で K に変換（`Te_K = Te_eV * e / k_B`）と **明示的な換算ロジック** が一箇所にまとまっている。
- E/N は内部 V·m²、表示時に Td（×10²¹）に変換。`format_si` で UI 表記を一元管理。

#### ✅ Shoelace 公式の Lissajous 面積積分
- V-q 平面上の閉曲線面積を `0.5·|Σ(V_k·q_{k+1} − V_{k+1}·q_k)|` で計算。離散点を結ぶ多角形の符号付き面積として **数学的に正確**。

#### ✅ Boltzmann plot の R² 計算
- `R² = (n·Sxy − Sx·Sy)² / [(n·Sxx − (Sx)²)(n·Syy − (Sy)²)]` の閉形式実装。線形回帰の決定係数として標準。LTE 直線性の **非経験的指標** として機能している。

#### ✅ TraceResult 抽象化
- 値・単位・LaTeX・代入・引用論文・異常判定 を **1 つの dataclass で持つ** 設計は、保守性とテスト容易性を両立。新しい物理量追加時に UI / Markdown / CSV すべてに自動反映。

### 3.2 改善提案

#### ⚠️ 提案 1: 変位電流補正の導入（Peeters & van der Laan 2015）
- 現状の Lissajous 法は `q = ∫I dt` の簡易版で、モニタコンデンサ Cm を介した厳密な Manley 法ではない。
- 液中ストリーマでは抵抗性支配なので大きく外れないが、**容量結合が強い実験条件** では真の P̄ から数十 % ずれる可能性。
- 改善: `Q_a = Q_plasma + Q_stray` の分離を `electrical/lissajous.py` にオプション追加。Cm 入力欄を Plasma タブに足す。

#### ⚠️ 提案 2: Stark 係数 α(Te) の Te 依存テーブル化
- 現状 α=1.0×10²³ m⁻³·nm⁻¹·⁵ 固定。
- 改善: Gigosos & Cardeñoso (1996) JPB 29:4795 の数値表を `plasma/stark_table.py` に埋め込み、Te を渡すと α を自動補間。
- 効果: 0〜30 % あった系統誤差が 5 % 以下に縮む。

#### ⚠️ 提案 3: パルス検出の hyperparameter チューニング UI
- 現状 `prominence=0.5·Vpp, distance=100 ns` が固定値。
- 実験条件によっては破断（Multi-streamer など）でこの値が合わない可能性。
- 改善: Sidebar に slider 追加、リアルタイムで N_pulses が変わる様子を Waveform 上で見せる。

#### ⚠️ 提案 4: 立ち上がり時間の検出窓を絞る
- 現状は **観測窓全体** で 10–90 % を判定。複数パルスがあると最初のパルス内ではなく窓全体の最大値で判定されて t_r が μs オーダーに膨張する事例あり（PW1.50 で 2.4 μs と表示される問題）。
- 改善: パルス検出後、**最初のピーク周辺 ±50 ns** に窓を絞ってから 10–90 % を再計算する高精度モード。

#### ⚠️ 提案 5: BOLSIG+ / LXCat 連携で EEDF を解く
- 現状の電子平均エネルギー ⟨ε⟩ は `0.02 · E/N` の経験式。
- 改善: BOLSIG+ コマンドラインを subprocess で呼んで、E/N → EEDF → ⟨ε⟩ を厳密化。LXCat の CO₂ 断面積セットを同梱。
- Phase 4 の拡張候補として明確に位置づけ。

#### ⚠️ 提案 6: 単体テストに数値解の比較を増やす
- 現状 49 テストのうち、解析解との **数値一致** を取っているのは正弦波の P̄=½V₀I₀cosφ 等の限定的なもの。
- 改善: 既知のリッチなベンチマーク（Manley 1943 の DBD オリジナルデータ、Mukasa 2009 の OES データ）を fixture として埋め込み、数値合致をパラメトリックテスト化。

### 3.3 総合評価（工学専門家視点）

> 「**研究室レベルの即戦力ツールとして完成度が高い**。離散化選択・単位系・抽象化・テスト網羅率のいずれも産業ソフト相当の質。Lissajous の変位電流補正と Stark 係数の Te 依存だけ改善すれば、SCI 論文の補助計算ツールとして自信を持って引用できる。」

## 4. 油合成研究者レビュー

> *仮想インタビュー: 液中プラズマ CO₂ 還元による液体燃料合成を 10 年以上研究するシニア研究者の視点*

### 4.1 評価できる点

#### ✅ A 軸（電力）が現場で必要な粒度をカバー
- ピーク値（Ppeak）も平均値（P̄）も累積（E）もパルスエネルギー（E_pulse）も全部出る。
- 実験ノートで「**今日の入力 mJ オーダー**」を即書ける。手計算なら 10 分かかっていた作業が 0 秒。
- **会議で決まった 1 kW 予算ルールが自動チェック** されるのは画期的。学生が条件設定を変えるたびに「装置壊さないか」を意識せずに済む。

#### ✅ B 軸（プラズマ診断）の R² LTE 判定
- 我々の研究で最大の論争点は「LTE 仮定が成立しているか」。これまで論文ではこの確認なしに Te を出していた。
- **R² ≥ 0.95 / ≥ 0.85 / < 0.85 の三段階判定** は、「査読されたら絶対突かれる」項目を毎回潰せる。**これだけで学会発表の質が一段上がる**。

#### ✅ C 軸（化学）の SEI / EC / χ / η_SE / ASF α 揃い踏み
- Snoeckx & Bogaerts (2017) の CSR レビューを全部読んだ研究者でないと出てこない指標群が、**最初から実装されている**。
- 特に **ASF α** が入っているのは衝撃。ここまで実装している大学研究室向けソフトは前例を見たことがない。
- 「α=0.85 でジェット燃料域、α>0.95 でワックス」という感覚を学生に教えるのに、画面で実物を見せられる。

#### ✅ 3 レベル解説の威力
- 新配属 B4 が「Vpp 11.8 kV って大きいんですか?」と聞いてくるたびに口頭説明していたが、**画面の 🔰 初学者解説で一発**。
- M2 の中間発表前に「この値は典型範囲か」を自分で確認できるようになるので、教員の手戻りが減る。

#### ✅ エラーラインと原因候補のセット表示
- これまでは異常値が出ても、原因の **当たりを付ける** までに教員に聞く必要があった。
- 「Vpp が下回っている → 電源出力不足 / プローブ分圧誤校正 / トリガ失敗」の 3 候補が出ることで、**学生だけで一次切り分け** ができる。指導者の負担が劇的に減る。

#### ✅ Public 化した GitHub リポジトリ
- xlsx 機密データを除外して **ソースコードと文書だけが公開**。
- 共同研究先（千葉さん側、東北大、上越大など）に URL を渡すだけで再現実験のためのソフトが共有できる。

### 5.4 メッセージ

本ソフトは野村研究室の 20 年の研究蓄積を **実装に変換した結果物**。
- オシロスコープ波形の数字
- 励起温度シートの計算
- 1 kW 予算ルール
- LTE 仮定の検証

これらすべては、過去の論文・会議議事録・研究者間の口伝で受け継がれてきた知識だった。本ソフトはこれらを **コードと自動チェックに翻訳** することで、新配属の B4 でも研究の入り口で迷わないようにした。

研究は競争領域でもあり、外部公開リポジトリにしたことで「**液中プラズマ油合成の標準計算ソフト**」を野村研究室発として打ち出すブランディング効果も期待できる。

油合成研究の最終ゴール「**CO₂ から液体燃料を実用化する**」までの道のりは長いが、計測 → 計算 → 判断のループを高速化することは、その距離を確実に縮める。本ソフトはそのための土台となる。
